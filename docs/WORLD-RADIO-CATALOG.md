# WILDBAND — Worldwide radio catalog and six-station sets

**2026-11-27 | Owner direction: worldwide discovery, up to six stations per saved set/patch, at most two simultaneous live receivers.** Implementation details below are proposed, not tested. Post-P0, P3 RADIO; preserve current tuner and audition builds.

## Experience

Separate discovery from performance. A station catalog is not a bank of receivers. A SET is an ordered collection of 0–6 station references, saved with patch settings. A new set can start empty or from a curated six-station factory template. EDIT SET opens a searchable directory; choose/reorder/replace/remove stations, add manual URLs, browse country/region, language and genre/tags. Search by name; show codec, reported health and last check, not a guarantee of playability. Optional city/map discovery only where reliable coordinates exist; no location permission required. Radio Garden is an inspiration for geographical discovery, not an API or visual asset to copy. Start with native list/search rather than a globe. No mandatory account. Selecting a catalog result for a slot does not start a network audio stream. Audition explicitly using one of the two receivers (no third preview stream).

Performance retains the six physical-style preset slots. Receiver A and B each select any occupied slot, with independent tuner position, detune/static, state, audio and broadcast-derived modulation; B disabled by default. Candidate UI: two colored receiver indicators on the six-slot strip and A/B focus for shared TUNE/NEXT/PREV/HOP controls, with independent MIDI mappings; audition before fixing layout. Skip empty slots. Explicit duplicate-station policy: initially disallow tuning both receivers to same station or offer intentional shared PCM fanout without extra network connection; no hidden duplicate downloads. A/B audio and LEVEL/HITS sockets distinct; optional mixer and cross-modulation. Preserve tails and captured volatile LOOP when either receiver retunes. LOOP capture source explicit A or B, not an additional receiver. No persistence of live PCM.

## Directory provider research

Use **Radio Browser** first, a community-maintained open directory:
- [Official integration guide](https://api.radio-browser.info/): free/open-source API for free and nonfree software, mirror discovery, descriptive User-Agent, click reporting; no key documented.
- [Official API reference](https://docs.radio-browser.info/) and [example mirror documentation](https://de1.api.radio-browser.info/): advanced search, stable station UUID, original and resolved stream URL, countrycode, state, languages/tags, codec/bitrate/HLS, last check and optional geographic coordinates.
- [Project site](https://www.radio-browser.info/) declares collected directory data public domain; API server software GPL. This does not license station logos, audio, third-party content or grant rebroadcast/capture rights. Prefer text metadata; omit logos initially. Credit provider and link station homepage when available.
- Radio Garden has a compelling discovery UX, but available community API descriptions are explicitly unofficial ([example](https://github.com/jonasrmichel/radio-garden-openapi)). No supported public integration or reuse permission verified; do not scrape or depend on internal endpoints. Curated factory stations plus manual URLs remain independent of provider.

No exact catalog size or availability guarantee asserted. Community data can be wrong, duplicated, stale, incomplete or malicious. No actual stream or API-client integration has been executed for this document; verify on target OS/network before promotion.

## API adapter proposal

Native C++/JUCE background service, independent of audio callback and decoder. No need for hosted backend or API key in initial design. Discover mirrors via DNS SRV _api._tcp.radio-browser.info or lookup/reverse lookup all.api.radio-browser.info as documented; randomize and fail over on bounded failures, HTTPS with normal certificate validation. Descriptive WILDBAND/version User-Agent, timeout, cancellation, backoff and bounded concurrency. Do not hardcode a single mirror or ship undocumented endpoints. Resolve provider URLs only on worker.

Illustrative GET requests relative to discovered HTTPS mirror:
- /json/countries and /json/languages and /json/tags for browse facets (cache).
- /json/stations/search?name=...&countrycode=JP&hidebroken=true&limit=50&offset=0 for paginated, URL-encoded search; optional language/tag/codec filters, stable sorting and dedup by stationuuid. Do not download entire directory at startup. Default hide recently broken and unsupported formats; allow explicit show-all with reasons.
- /json/stations/byuuid/{stationuuid} for refresh by stable identity (verify current endpoint semantics against API reference).
- /json/url/{stationuuid} for genuine user playback selections per provider guidance. Disclose that request reports a station selection to provider; no user identity, fake clicks, background polling clicks or retry inflation; confirm how to handle automatic HOP with provider, respect privacy policy and offer appropriate opt-out if needed. Playback must not depend on analytics success.

Use typed DTO validation, response size limit, UTF-8/text length limits, pagination, cancellation tokens, debounce ~300 ms and result generation IDs. Cache bounded results/facets off callback (candidate TTL 24 h, stale indication), keep saved station snapshots local. Avoid aggressive polling, station health mass probes or automated discovery playback. No compulsory account or tracking; disclose that directory and station servers see normal network connection metadata/IP. No secrets in code. No remote HTML execution.

## Data model / persistence

StationRef { source: radioBrowser|manual|factory, stationUuid?: UUID, displayName, originalUrl, lastKnownResolvedUrl?, countryCode?, region?, languages?, tags?, codecHint?, hlsHint?, checkedAt? }. Stable UUID across mirrors, not provider numeric ID. Manual entries use local stable ID. Names/metadata are display-only untrusted text. A set contains schemaVersion, ordered slots (max 6, stable slot IDs; empty allowed), receiver A/B slot refs and independent tuner parameters/enabled state, MIDI and patch graph settings. No audio or live history. Existing six presets migrate without loss and B defaults off; legacy patches retain A routing and behavior. Validate unknown fields and invalid refs; preserve missing station slot and user-entered URL, allow replacement; do not silently substitute another station. Restore configuration without needing catalog network. Honor existing consent/transport policy; no preview or hidden background connections on catalog browse/restore. Refresh saved URLs explicitly or on tune failure with bounded provider lookup and clear status; preserve manual override. No provider-wide download in DAW state; no secrets or captured content.

## Streaming and compatibility

P0 currently accepts direct MP3/AAC HTTP(S) with AudioToolbox. Treat catalog codec/hls/health as hints; verify real content and decoder readiness. Prefer url_resolved for direct stream, retain original as reference; if stale refresh by UUID or safely resolve bounded playlist/redirect chain. Start with supported direct MP3/AAC only; exclude HLS/Ogg/Opus/FLAC until separately qualified. Metadata may mislabel AAC, AAC+, bitrate and container; test actual variants. No arbitrary transcoding/proxy service. Classify unsupported codec, geo-block, TLS failure, timeout, malformed stream, empty slot and provider offline; do not bypass access controls. Verify HTTP cleartext policy with AUv3 separately. Validate schemes HTTP(S), no embedded credentials or unsafe URI forms, cap redirects/playlist bytes/depth, block loopback/private/link-local/metadata endpoints and DNS rebinding for untrusted catalog entries (including redirects); explicit separate consent for developer/local manual stream testing, not a bypass for directory entries. No shell execution, unbounded downloads or trust in favicon/homepage links.

## Dual receiver design

Two independently owned stream/decode workers and bounded stereo PCM queues, per-receiver generation IDs, readiness, cancellation, rate conversion, health and static envelope. Strict scheduler budget: at most two active stream sessions per instrument instance, including preview/retune; close superseded transport before opening replacement rather than overlap a third connection. Pending jobs bounded; latest tune wins independently per receiver; no parallel prebuffer of all six. Factory/patch restore can choose one or two enabled paths subject to explicit network policy. Multiple plugin instances each have max two; investigate process-wide resource/bandwidth limits and helper isolation, don't silently impose a global single instance.

A/B independently provide AUDIO, broadcast-only LEVEL/HITS and optional separate tuner activity; static fills only actual requested buffer gap, never fake live signal, no automatic hopping self-loop. Per-source gain/mixer, headroom for simultaneous peaks and downstream feedback, stereo routing and phase; preserve existing A-only reference behavior. B failure must not mute A; B disabled releases resources. Local test source remains available. PANIC silences both and stops capture, with network lifecycle explicit. No network, DNS, JSON, disk, locks, allocation or unbounded work on callback. Test AUv2/VST3 and AUv3 separately; host lifecycle and offline render do not imply deterministic live audio.

## Work stages and gates

R0 provider spike: verify actual DNS/API calls, response fields, paging/cancellation, sample varied countries/languages/codecs and stale/broken cases, actual MP3/AAC stream probe from representative results. Record timestamp, failures, source terms, no audio fixtures from broadcasters without rights. No exact count unless queried and labeled.
R1 set model: migration, add/remove/reorder 0–6, manual URLs, save/restore per patch, missing entries and duplicate policy, offline provider outage, malformed input, no network on browse/add. R2 browser: searchable native UI, facets, paging/cache, accessibility, keyboard/MIDI-friendly performance return. R3 dual receiver: separate selection and signals, explicit preview budget, retune/fail one while other live, two independent static layers, rapid hopping, stale generations, source mixer and cross-modulation. Verify live socket/session limit under races, no leaks, no third connection, A-only parity. R4 qualify combined CoreAudio/hosts at target rates/buffers, both live + chosen DSP + LOOP + WORLD, callback tails/allocations/underruns, multiple instances, network loss, sleep/wake, restore and clean-machine behavior. R5 owner audition: build a six-station set across countries, perform A/B switching, cross-modulation and LOOP against new broadcast; verify immediacy and no disruption by directory outage.

Prioritize searchable worldwide catalog + six-slot sets and two-receiver path as core product requirements; stage work in P3 with early architecture spike, no change to P0 acceptance and no unqualified release. Fancy globe/map, bulk offline mirror, additional providers, more formats and prebuffering are future/optional. Keep January 14 feature freeze and contest-eligible plugin delivery protected; report scope risk rather than silently expanding.
